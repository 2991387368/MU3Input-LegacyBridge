# 测试矩阵与故障报告

## 自动离线测试

先运行根目录 `build.ps1` 构建fake和测试，再运行 `test.ps1` 验证本次构建并执行。测试目录的 `fake_original.c` 是测试替身，**不是原版IO**，不可部署到真实宿主。

| 测试 | 范围 |
| --- | --- |
| test_encode | 65B报文、board/空指针/长度、亮度钳制、六灯映射、零填充、重叠缓冲 |
| test_forward | fake原函数ABI与参数/返回、缺失同目录原DLL的失败路径、辅助出口 |
| test_lifetime | 注入写入/取消/完成边界，验证pending期间不复用OVERLAPPED和buffer，互斥量 |
| test_scheduler | 生产worker配模拟时间/设备：空闲让权、同色断连重开与后续同色重发、event失败重试 |
| 构建约束 | x64静态断言、严格警告作为错误 |

脚本包含编码、转发成功、原DLL缺失、I/O寿命、调度五组运行；不会初始化真实原IO或测试实机灯。模拟测试不等于某个真实驱动会正确完成取消。

## 单设备现场验证（历史汇总）

- 低亮度40/255，左三灯/右三灯依次红绿蓝，最后全灭：由操作者确认。
- 接桥后的后台约119秒运行，检查时响应，未见新增应用错误；未运行完整游戏流程。
- 桥输入探针约12秒，584个样本保持连接。该次没有逐键/全摇杆复测，不能把保持连接说成全输入验收；探针轴值停在端点，桥没有轴变换。
- 早先原IOConfig输入路径由操作者确认六主键、侧键、摇杆正常。这不代替桥在完整宿主中的逐项验证。

不公开个人设备标识、机器用户名、现场绝对路径、原始游戏日志。这里的结论是一次设备观察，不是兼容性认证。

## 未覆盖

- 完整游戏启动及长期灯效/输入压力。
- 实际拔插恢复（目前仅模拟调度测试）。
- 多台控制器和不同固件/克隆板。
- 不同进程同时输出不同颜色的优先级、不同Windows会话。
- 失常驱动永不完成取消、系统挂起/休眠、第三方软件并发写入。
- 原IO内部输入接收/异常处理和Aime真实卡读写行为。

## 安全的手动验收顺序

1. 使用离线测试先验证构建。
2. 退出所有相关进程，备份配置；只保留一个输入实例。
3. 首先以 `enabled=0` 验证有效JSON、输入和进程启动，再退出。
4. 在明确了解固件协议后，`enabled=1`、低亮度，单进程检查六灯及全灭。
5. 最后再试多进程/完整宿主；保持USB可拔与明确退出方式。不要把仅枚举成功当作全部通过。

本项目不附自动实机灯光测试脚本，避免在不知情时访问硬件。不要求刷写固件。

## 报告问题前

- 先排除 HID `Param:null` 和默认/重复 UDP 绑定；这些不是灯光编码问题。
- 确认桥及原DLL均x64、文件名/同目录正确、两个入口都指桥。
- 修改配置后重启所有相关进程；INI不会热更新。
- 暂时 `enabled=0` 可把灯光与输入路径分开；切勿把稳定启动等同完整游戏成功。
- 不要附原DLL、固件、游戏文件、卡号或未脱敏日志。

Issue应包含：Windows版本/架构、原IO版本及可选SHA256、桥的版本/构建工具、去掉个人信息的设备VID/PID/usage、复现步骤、是否单进程、enabled=0的对照结果。路径、序列号、容器ID、卡信息和网络配置须自行脱敏。
